## 一、为什么原页面不显示 god-eye-view 的样式

排查时用 headless Chrome 抓了控制台和场景状态，定位到 **4 个真实故障**，不是样式表没写好，而是页面根本没有渲染出来。

### 1. Cesium 引擎三个 CDN 全部失效（致命）

原页面按顺序尝试 jsdelivr → unpkg → staticfile 三个源：

| CDN | 实测结果 |
|---|---|
| cdn.jsdelivr.net | 连接超时（10s+，国内不可达） |
| unpkg.com | 连接超时（10s+） |
| cdn.staticfile.org | HTTP 404，该站没有 cesium 1.124.0 |

三个全挂，`window.Cesium` 永远是 undefined，地球、飞机、轨迹一个都不会出现。

### 2. 高德瓦片子域拼接错误（致命）

```js
// 原代码
url: "https://webrd{s}.is.autonavi.com/..."
subdomains: ["0", "1", "2", "3"]
```

拼出来是 `webrd0`、`webrd1`、`webrd2`、`webrd3` —— **这些域名不存在**。
高德的正确子域是 `webrd01` ~ `webrd04`（两位数字）。实测全部 `ERR_NAME_NOT_RESOLVED`，所以即使引擎加载成功，地球也是一颗纯黑的球。

### 3. 飞机实体一个都没创建成功（致命）

页面状态实测：`polylines: 1097`、`billboards: 0`，但内部字典 `bbKeys: 1098`。
说明 Entity 被创建了，却全部没能进入场景 —— 用 SVG data URI 直接喂 Cesium `Entity.billboard.image` 的解码路径有问题，静默失败，捕获不到异常。结果就是轨迹线在飘、飞机一架都看不见。

### 4. 一串连带 bug

- `renderAll()` 里没有调用 `renderList()` → 数据加载完列表永远是空的
- `alt` 已经是米，却又乘了 `0.3048`（英尺换算）→ 10668 m 被压成 3.2 km，飞机贴地
- `vel` 是 m/s，按 `*1.852`（节→km/h）算 → 地速显示偏大近一倍
- 输入完整航班号 `CCA1501` 会把全部 38 架国航都捞出来

## 二、这次改了什么

### 引擎层
- Cesium 1.124.0 **整套 vendor 化到 `vendor/cesium/`（14 MB）**，页面零外部 CDN 依赖；万一本地缺失，自动回退 `registry.npmmirror.com`（国内实测 5 MB / 1.2 s）。
- 数据源从 `raw.githubusercontent.com` 改为同站点相对路径 `../data/`（raw 域名在国内不稳定）。

### 渲染层（`cesium/3d.js` 全部重写）
- 改用 **`BillboardCollection` + `PolylineCollection`** 原生 primitive，弃用 Entity API。这是 god-eye-view 本身的做法：千级目标下 Entity 的 Property 开销过大，且 primitive 对实例生命周期可控。
- 机型图标先 **canvas 光栅化再贴图**，绕开 SVG 解码的坑（原 0 架飞机就是这么来的）。
- 修正 `alt` / `vel` 单位、补齐列表刷新、修正航班号精确匹配。
- **快照去重**：后端 15 分钟才更新一次，10 秒轮询拿到同一份数据时不再重绘，避免列表每 10 秒重建一次打断你的滚动和点击。

### 视觉层（对齐 gods-eye-view 的 `foundation.css` 设计 token）
- 配色改用 god-eye-view 原版：底色 `#0a0a0f`、主色 **`#00d4ff`**、玻璃面板 `rgba(12,12,20,0.72)` + `backdrop-filter: blur(22px)`（原页面用的是蓝色 + 绿色，不是它的色系）。
- 布局从「左侧固定栏 + 右侧地图」改成 **满屏地球 + 悬浮玻璃 HUD**——这是 god-eye-view 最标志性的结构差异。
- 底图换成高德**卫星影像**，叠加半透明路网；加 **bloom 发光后处理**，飞机与轨迹才有那种光晕。
- 地表明暗随相机高度自适应：远景压暗出氛围，贴近地面自动提亮看清地貌（含色相回落，近距离还原真实色彩）。
- 新增等宽字体的实时读数（经纬度 / 视高 / FPS）、星空背景、扫描线暗角。
- 飞机按距离缩放（`NearFarScalar`），全球视角下密集空域不会糊成一团光斑。

## 三、怎么上线（保持原 URL 不变）

在终端依次执行。**注意排除 `data/`**，那是最新航班数据，别用本地旧数据覆盖它：

```bash
# 1. 克隆一份最新仓库（保留 Actions 的历史提交）
git clone https://github.com/makacy-999/flight-tracker.git ~/ft-deploy
cd ~/ft-deploy

# 2. 把新版本覆盖进去（排除 data 和 .git）
rsync -av --exclude data --exclude .git \
  /Users/makacyguo/WorkBuddy/2026-10-23-14-04-47/flight-tracker/ ~/ft-deploy/

# 3. 提交并推送
git add -A
git commit -m "fix: 修复 3D 页面渲染（Cesium 本地化/高德子域/飞机 primitive 重写）+ god-eye-view 视觉重做 + 新增微信小程序"
git push origin main
```

推送需要 GitHub 凭据（本机未配置 `gh` 和 credential helper，需要输入账号 + Personal Access Token，或用 GitHub Desktop 推）。

推送后 GitHub Pages 大约 1~2 分钟生效，刷新原 URL 即可。

> vendor 目录 14 MB，推送会慢一点，属正常。GitHub 单文件上限 100 MB、仓库建议 1 GB 以内，14 MB 完全无压力。

## 四、微信小程序

目录：`miniprogram/`

### 本地跑起来
1. 打开 **微信开发者工具** → 导入项目 → 目录选 `miniprogram/`
2. AppID 选「测试号」即可
3. 右上角 **详情 → 本地设置 → 勾选「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」**（必须勾，否则拉不到航班数据）

功能：全屏地图 + 机型图标（按航向旋转）+ 航班号/航司/中文名搜索 + 点击看详情 + 轨迹线。

已用 Node 模拟微信环境跑通数据链路，实测结果：

```
总架数 1097 ｜ 单屏 markers 200（上限截断，保帧率）
搜 "CCA"    → 38 架     搜 "国航" → 38 架
搜 "CCA1501" → 1 架（精确匹配）
详情：CCA1501 中国国际航空 10.70km 852km/h 航向174° ICAO24 781AC4
```

### ⚠️ 上线前必须知道的硬限制
小程序要求所有 `request` 域名在小程序后台备案登记，**`*.github.io` 无法备案**。所以：

- 开发/自用：勾掉域名校验就能用（现在就是这个状态）
- 要正式发布：两种做法
  1. 买个已备案域名，做个反向代理指向 GitHub Pages
  2. 用微信云开发云函数中转请求（无需自己备案域名，推荐）

需要我接着做云函数中转的话说一声。

### 关于「实时」
现在的数据是 GitHub Actions 每 15 分钟抓一次 OpenSky 的快照，**有最多 15 分钟滞后**，不是真实时。

要真实时有两条路：
- 小程序直连 OpenSky 官方接口（`app.js` 里 `USE_REALTIME` 开关已预留）：匿名限制约 10 秒/次、400 次/天，且国内直连不稳
- 自建后端定时拉取 + 缓存（推荐，可控且稳）
